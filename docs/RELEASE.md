# Релизы Android и ключ подписи

CI собирает APK на каждый PR и на каждый пуш в `main`. Сборки из `main` публикуются в **Releases** репозитория.

Android обновляет установленное приложение, только если у нового APK **та же подпись** и **больший номер версии**:
- номер версии CI ставит сам, это номер запуска CI (`--build-number=${{ github.run_number }}`);
- подпись — ваш релизный ключ, который CI берёт из GitHub Secrets.

Пока ключа нет, каждая сборка подписывается случайным одноразовым ключом. Чтобы поставить новую сборку, старую придётся удалить вместе с прогрессом.

> ⚠️ **Ключ нельзя терять.** Если вы потеряете ключ или пароль, выпустить обновление существующего приложения будет невозможно (в Google Play — только через процедуру сброса upload-ключа). Сохраните файл `.jks` и пароль в менеджер паролей и ещё в одно место.

## Текущий ключ

Ключ создан 17.10.2026: alias `bytecraft`, RSA 4096, срок действия до 2054 года.
Отпечаток сертификата (SHA-256):

```
70:0C:AE:F9:7B:A7:DA:F6:8E:F4:2B:10:AE:C5:38:E1:91:0C:28:4E:90:09:91:69:5E:56:76:A8:E6:B5:31:0D
```

В комментарии CI к PR и в разделе **signing** должен быть этот же отпечаток. Если отпечаток другой, сборка подписана не тем ключом.

Ниже — как создать ключ заново, если понадобится (например, для другого приложения).

## 1. Создать ключ (один раз)

Понадобится `keytool`: он входит в Java (JDK) и в Android Studio. Проверить, есть ли он: `keytool -help`.

```bash
keytool -genkeypair -v \
  -keystore bytecraft-release.jks \
  -storetype PKCS12 \
  -alias bytecraft \
  -keyalg RSA -keysize 4096 \
  -validity 10000
```

`keytool` спросит пароль (не короче 6 символов) и данные владельца. Имя, город и страну можно указать любые, их видно только в сертификате.

## 2. Превратить ключ в текст

macOS (результат сразу окажется в буфере обмена):
```bash
base64 -i bytecraft-release.jks | pbcopy
```

Windows (PowerShell):
```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("bytecraft-release.jks")) | Set-Clipboard
```

Linux:
```bash
base64 -w0 bytecraft-release.jks
```

## 3. Добавить секреты в GitHub

Откройте репозиторий → **Settings → Secrets and variables → Actions → New repository secret** и создайте четыре секрета:

| Имя | Значение |
|-----|----------|
| `ANDROID_KEYSTORE_BASE64` | текст из шага 2 |
| `ANDROID_KEYSTORE_PASSWORD` | пароль из шага 1 |
| `ANDROID_KEY_ALIAS` | `bytecraft` |
| `ANDROID_KEY_PASSWORD` | тот же пароль (у PKCS12 он совпадает с паролем хранилища) |

## 4. Проверить

Перезапустите CI в любом открытом PR или сделайте пуш. В комментарии CI должно быть написано `release-signed=true`, а в разделе **signing** — отпечаток (SHA-256) вашего сертификата. Отпечаток стоит сохранить рядом с ключом.

## Что ещё нужно знать

- Первая сборка с релизным ключом не встанет поверх сборок с одноразовым ключом: их нужно удалить один раз. Дальше обновления ставятся поверх.
- Старое приложение CodeQuest имеет другой идентификатор (`com.pazzia.codequest_mvp`) и Bytecraft (`com.pazzia.bytecraft`) не обновит. Его можно просто удалить.
- Для Google Play позже понадобится AAB (`flutter build appbundle`) с тем же ключом в роли upload-ключа. Это отдельный шаг в CI, сделаем его при подготовке к публикации.
