# Исполняемый проект: калькулятор

Этап 4, версия 0.7.1. Проверки CI обязательны до закрытия этапа.

Проект открывается после пяти этапов экспедиции. Пользователь пишет свою программу на Python в пустом редакторе. Четыре компонента: calculate с четырьмя операциями, список history с результатами, ошибки деления на ноль/неизвестной операции, run_calculator с разбором строк и понятными сообщениями. Проверки запускаются в существующем PythonRunner на устройстве; каждый шаг повторно проверяет и предыдущие функции. Количество проверок: 5, 6, 9, 14.

Черновик автоматически сохраняется после паузы ввода, явно кнопкой и до проверки. При уходе выполняется дополнительная попытка сохранения. Проверенный финальный код хранится отдельно от изменяемого черновика и доступен для копирования. Неисправленный черновик не заменяет последнюю рабочую программу.

Награда компонента: 45 XP и 25 монет до бонусов зданий; после неудачных проверок — 22 XP. Для миграции компонентов, за которые уже начислялась награда в старом проекте-вопроснике, повторной валюты нет. Квитанцией служит завершённый номер этапа вместе с сохранённым результатом. Изменившийся во время проверки код, неполный ответ проверяющего скрипта, неправильный nonce, недоступный Python или отказ сохранения не продвигают этап и не выдают награду.

Босс требует отдельный флаг hasVerifiedProject, который выдаётся после всех 14 проверок кода. Старые ответы на четыре вопроса больше не могут открыть босса. Старые монеты и достижения не удаляются.

Проверки Python проверяются независимо в CPython эталонной программой и намеренно ошибочными решениями; CI повторяет их. Тесты сервиса проверяют перезапуск, гонки, изменение кода во время выполнения, отказ записи и сохранение последней рабочей версии. Это проверка функциональности программы, а не профессиональная аттестация автора.

## Исправления 0.7.1 — 19 октября

- История проверяется после каждой из четырёх операций. Раньше программа, теряющая вычитание или умножение, проходила проверку истории.
- Отладочная печать ученика в stdout и stderr подавляется на время автоматических проверок и не переполняет отчёт.
- Приложение проверяет состав и порядок проверок, типы результатов и nonce. Одинаковое число повторённых проверок не заменяет полный отчёт.
- Повреждённый, неполный или чужой отчёт не засчитывается как ошибка ученика и не снижает будущую награду. Ошибки Python в программе и превышение пяти секунд учитываются как неудачные попытки.
- Неудачная проверка без подробностей больше не подписывается «пройдено». При редактировании исчезает отчёт о предыдущем коде; последняя проверенная программа хранится отдельно.
- Локальная подготовка платформ использует идентификатор bytecraftworld; сверка генератора сравнивает весь каталог контента.

Регрессии: 8 тестов CPython, 9 сценариев калькулятора в Pyodide (включая потерянные операции и большой stderr), тесты сервиса и экранного перехода. Полный конвейер Android проверяет анализ, Flutter-тесты, подпись APK и запуск в эмуляторе.

Дополнительно `dart tool/projects/check_service.dart` проверяет настоящий ProjectService с CPython и сохранениями без запуска Flutter: четыре этапа, повреждённый отчёт, синтаксическую ошибку, неполную историю, размер награды, повторную проверку и сохранение последнего рабочего кода. Этот сценарий включён в CI.

Следующий незавершённый этап — работа над ошибками: подтверждение исправления новым самостоятельным решением, связь с конкретной подтемой и сохранение доказательства закрепления. Существующее уменьшение счётчика по широким категориям не закрывает этот этап.
