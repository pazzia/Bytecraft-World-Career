# Проект Обучалка

## Идеи обсуждения и решения по развитию Bytecraft

**Дата свода:** 18 октября 2026 года. **Период обсуждений:** октябрь 2026 года, от выбора идеи мобильной головоломки до Bytecraft World 0.4.0.

Проект начался с поиска мобильной игры с возможностью монетизации и развился в обучающую платформу по программированию. Центральная идея — короткие практические задачи в формате Duolingo, за которыми следует применение знаний в игровом мире и, в карьерном направлении, подтверждение навыков и подготовка к работе.

Документ объединяет первоначальные варианты игры, выбранную концепцию, учебные механики, карьерные идеи, игровой мир, монетизацию, технические решения и историю исправления логики. Он служит общей картой проекта для владельца продукта и разработки. Статусы «идея», «прототип» и «реализовано» обозначают разную степень готовности; наличие пункта в обсуждении не означает наличие готовой функции в приложении.

## 1 Основные договорённости

- Создать мобильную обучающую игру по программированию с перспективой монетизации.
- Взять за основу формат Duolingo, адаптированный к программированию и головоломкам.
- Начать с Python; расширение на другие языки рассматривать после работающего учебного ядра.
- Давать короткие задания, которые можно решить за 1–3 минуты, и более длинные испытания для продвинутых пользователей.
- Связать обучение с понятным результатом: освоенным навыком, работающим проектом, ростом игрового мира или карьерным доказательством.
- Сохранить интерес после завершения начального курса: практика, соревнования, проекты, аттестация и карьерные цели.
- Развивать экспериментальные направления в отдельных форках с собственными названиями и версиями, чтобы установленные приложения не путались.
- Реализовывать именно согласованный концепт и макет. Для World пользователь отдельно отверг повторение старого интерфейса и плоскую картинку вместо настоящей графики.
- Обеспечить осмысленную логику: нельзя проходить уровни нажатием «выполнено» без решения; правильные ответы и ошибки должны менять прогресс.

**Ключевая формулировка пользователя:** «Игра должна иметь смысл, уровни должны меняться, выполнения и ошибки выполнения влиять на прогресс».

## 2 Как развивалась концепция

### От обычной головоломки к обучению

Первый запрос касался десяти идей мобильной puzzle-игры с монетизацией. Среди первоначальных рекомендаций выделялись Crime Board, Tiny Heist и Broken Reality. После этого выбран вектор «типа Duolingo, но по программированию». Перечень всех десяти исходных вариантов сохранён в приложении в конце документа.

Появилась идея объединить обучение и развитие виртуальной IT-компании. Разные дисциплины должны усиливать разные направления: Python — Backend, JavaScript — Frontend, SQL — Database, алгоритмы — Performance. Это продуктовая концепция развития, а не перечень уже выпущенных курсов.

### От курса к карьерной платформе

Следующий шаг — использовать самые сложные задания как часть аттестации разработчиков и помогать пользователю собирать сильное резюме. Ценность должна сохраняться и для человека, который уже умеет программировать: он приходит подтвердить уровень, найти пробелы, улучшить портфолио и подготовиться к конкретной работе.

Карьерная последовательность обсуждалась как Learn → Practice → Prove → Build portfolio → Get hired: изучить, потренироваться, доказать, собрать портфолио, подготовиться к трудоустройству. Последний пункт обозначает направление продукта, а не гарантию получения работы.

### От учебной оболочки к игровому миру

Отдельное направление Bytecraft World возникло вокруг макета с десятью игровыми механиками. Потребовались собственный игровой главный экран, графический город, экспедиция, босс, соперник и другие режимы. Пользователь уточнил, что нужен самостоятельный игровой продукт по макету, а не очередной редизайн уже существующего Bytecraft.

После графического обновления обнаружилось, что многие действия меняют состояние без проверки знаний. Приоритет сместился к полноценной логике заданий, последовательности этапов и реальным последствиям ответов. Это стало содержанием версии World 0.4.0.

Для World закреплён Android package `com.pazzia.bytecraftworld`. У него собственная иконка и сборка. Отдельный PR № 12 оставлен для экспериментальной продуктовой линии; выпуск World 0.4.0 в этом обсуждении не означал слияния с main.

Career и World — разные эксперименты на общей учебной базе. Автоматическое объединение всех функций обоих форков в один готовый продукт не зафиксировано.

## 4 Учебный продукт

### Основной цикл

Пользователь выбирает опыт и курс, открывает тему, решает задание, получает проверку и объяснение, после чего видит награду и доступный следующий шаг. Ошибка должна подсказывать, что именно не понято, и возвращать тему в тренировку. Простое увеличение счётчика экранов не считается обучением.

Короткий цикл рассчитан на 1–3 минуты. Более длинные задачи, забеги, боссы и проекты дают возможность продолжить сессию и применить несколько навыков вместе.

### Форматы заданий

| Формат | Суть | Состояние в проекте |
| --- | --- | --- |
| Code Ordering | Собрать программу из строк в правильном порядке | Есть в учебном ядре |
| Find the Bug | Найти ошибочную строку или участок кода | Есть в учебном ядре |
| Predict Output | Предсказать результат выполнения | Есть в расширенном курсе |
| Fill Missing Code | Заполнить пропуски | Есть в учебном ядре |
| Type Output | Ввести результат самостоятельно | Есть в расширенном курсе |
| Match Pairs | Сопоставить связанные элементы | Есть в расширенном курсе |
| Multi Select | Выбрать несколько верных ответов | Есть в расширенном курсе |
| Написание программы | Решить задачу кодом и пройти тесты | Есть в Python-практике и песочнице |
| Code Maze | Управлять прохождением лабиринта через код | Обсуждавшаяся идея |
| Optimization | Улучшить решение по эффективности | Обсуждавшаяся идея отдельной механики |
| Debug Battle | Испытание по поиску и исправлению ошибок | Обсуждавшаяся идея |
| Boss Level | Проверить несколько навыков в сложном испытании | Есть отдельные реализации в обучении и World |
| Code Duel | Состязаться в решении задачи | Идея развития; полноценная сетевая дуэль не подтверждена |
| Daily Bug | Ежедневная задача на ошибку | Идея ежедневного повода вернуться; базовый daily challenge предусмотрен |

### Курс Python

В раннем плане обсуждалось движение к 100 уровням по переменным, типам, операторам, условиям, циклам, строкам, спискам, словарям, функциям и алгоритмам, с итоговым проектом. Первые MVP были существенно меньше: в разных этапах фигурировали 20 уровней и затем 25 уровней с четырьмя механиками. Эти числа относятся к разным стадиям.

В расширенной учебной базе, использованной при работе над World 0.4.0, проверка контента показала 37 модулей, 367 уровней, 106 тем и 47 практических задач. Поздние модули охватывают ООП, типизацию, тестирование, файлы, стандартную библиотеку, асинхронность, потоки, процессы, производительность и организацию проекта.

После Python обсуждались JavaScript, SQL, Java, C#, C++, Go и Rust. Это направления расширения, а не готовые курсы текущего релиза.

### Объяснения и закрепление

В проект заложены подсказки, объяснения после ошибки, разбор фактического вывода программы и карточки тем. Отмеченную тему или тему с ошибкой можно сохранить в журнал и повторять. В учебной реализации используется интервальное повторение по схеме Лейтнера с интервалами 1, 3, 7, 16 и 35 дней.

Python-песочница позволяет писать и запускать код на телефоне. Для практических задач важна проверка входных и выходных данных тестами, а не совпадение текста решения с одним образцом. Игровые задачи World 0.4.0 используют отдельный формат ввода результата или выбора исправления; их не следует путать со свободным выполнением кода в песочнице.

## 5 Геймификация и режим на время

### Учебная мотивация

Обсуждались и развивались XP, звёзды за качество решения, монеты, уровни аккаунта, жизни, ежедневная серия, заморозка серии, достижения, задача дня, карта курса, профиль и статистика. Для опытного пользователя предусмотрена возможность начать с разных модулей, а не обязательно проходить все основы подряд.

В стандартных правилах учебного ядра зафиксированы пять жизней и восстановление одной жизни за 30 минут. Три звезды даются за прохождение без ошибок, две — с одной ошибкой, одна — при большем числе ошибок. Повторный уровень приносит уменьшенный XP и не должен повторно выдавать награду за первое прохождение.

Учебная экономика и отдельная экономика World имеют разные правила. Например, базовые пять учебных жизней нельзя переносить на бесконечный режим World, где начальный запас равен трём.

### Исходная идея хардкорного режима

Пользователь предложил ограничить прохождение рубрики таймером, например десятью минутами. По исходной формулировке отсчёт должен начинаться после первого примера. Если до нуля не закрыты все примеры рубрики, ранее пройденный пример теряет статус пройденного.

Смысл идеи — проверить освоение всей группы заданий в ограниченное время, придать ошибкам и задержкам реальные последствия и создать повод вернуться к тренировке.

### Реализованный вариант забега

В учебном коде режим «На время» оформлен как отдельный забег модуля. Он запускается кнопкой «Старт», хранит дедлайн и временный набор пройденных в забеге уровней. Просроченный забег сбрасывается; постоянные отметки о прошлых наградах и рекордах сохраняются, чтобы нельзя было бесконечно получать повышенный XP за одни и те же задания.

Для первого прохождения на время предусмотрены повышенный XP и бонус за скорость. Повторный забег может обновить рекорд, но не создаёт новое первое прохождение.

**Различие, требующее отдельного решения:** исходный старт после первого примера и текущий старт по кнопке — разные правила. Также не следует автоматически трактовать временный сброс забега как удаление всего постоянного учебного прогресса. Эти варианты нужно согласовать перед дальнейшим изменением режима.

## 6 Карьерное направление

### Пользовательская идея

Пользователь предложил сделать самые сложные задания частью аттестации разработчиков и помогать разработчикам создавать сильное резюме. Затем попросил добавить эти механики как причину пользоваться системой постоянно и увеличить время в программе, разрешил реализацию форка и потребовал отдельное название и версию приложения.

Карьерная ценность должна опираться на доказательства: какие задачи человек решил, какие проекты сделал, как прошёл проверку и какие пробелы остаются относительно выбранной роли.

### Паспорт навыков

Обсуждался Skill Passport с тремя состояниями: Learned — изучено; Practiced — отработано; Verified — подтверждено проверкой. Прохождение курса и подтверждённая квалификация должны различаться.

Career Score и readiness должны показывать прогресс относительно карьерной цели и помогать выбрать следующий полезный шаг. В концепции упоминались Python Core, Algorithms, Testing, Async, SQL и System Design. В прототипе Career выделены шесть групп: Python Core, ООП и архитектура, алгоритмы, тестирование, async и concurrency, production skills.

Для прототипа предусмотрены цели Junior Python Backend, Python Backend Developer и Strong Middle Python Backend. Расчёт по завершённым уровням, звёздам и GitHub-признакам даёт ориентир, но сам по себе не является независимой аттестацией.

### Три уровня подтверждения

| Уровень | Обсуждавшаяся проверка | Состояние |
| --- | --- | --- |
| Course Completion | Завершение курса и учебных заданий | Учебный прогресс существует |
| Bytecraft Verified Skill | Ограниченное время, незнакомые задачи, скрытые тесты, анализ кода, пауза перед пересдачей | Концепция развития аттестации |
| Professional Certification | Испытание примерно на 90 минут с debugging, алгоритмами, обработкой данных, разработкой функции и ревью AI-кода | Концепция, не подтверждённый готовый сервис |

Для серьёзной аттестации обсуждались защита от недобросовестного прохождения и прокторинг. Конкретный поставщик и регламент не закреплены. Нельзя выдавать локальный игровой процент за внешний профессиональный сертификат.

### Резюме и портфолио

Обсуждались AI CV, Resume Score, Portfolio Passport и сборка карьерного профиля из проектов, подтверждённых навыков, GitHub и coding activity. Резюме должно показывать не только список технологий, но и подтверждаемые результаты.

В ветке Career есть прототип получения публичных GitHub-данных и оценки признаков проектов: основной язык, тесты, CI, Docker, конфигурация пакета и другие метаданные. Есть генератор текстового черновика CV. Он собирает сведения об учебном прогрессе и проектах; перед использованием пользователь добавляет реальный опыт, компании, достижения и контакты.

Наличие README, тестов или Docker-файла — признак проекта, а не достаточное доказательство авторства и уровня разработчика. Продвинутая верификация и AI-редактор резюме остаются отдельными частями концепции.

### Работа с вакансиями

Vacancy Match должен сопоставлять требования вакансии с текущими навыками, показывать пробелы и предлагать Career Sprint — целевую подготовку под нужную позицию. В прототипе есть сопоставление вставленного текста вакансии по ключевым словам с группами навыков.

Обсуждались Interview Arena, тренировочные интервью и задачи работодателей. Также предложен Bytecraft Talent — доступный работодателям пул кандидатов с добровольным участием пользователей. Действующий сервис найма, интеграции с работодателями и публичный каталог кандидатов не подтверждены как выпущенные функции.

## 7 Причины возвращаться в приложение

Пользователь отдельно сформулировал цель постоянного использования. Обсуждались поводы разной длительности — от короткого действия на три минуты до карьерного движения на 6–12 месяцев.

| Горизонт | Обсуждавшиеся механики | Польза для пользователя |
| --- | --- | --- |
| Каждый день | Daily Bug, daily challenge, Career Quests, streak, Job Streak | Небольшой понятный шаг и регулярная практика |
| Несколько сессий | Работа с ошибками, интервальное повторение, последовательность проекта, карьерный спринт | Закрытие пробела и применение знаний |
| Каждую неделю | Weekly review, skill check, интервью, командный проект | Проверка устойчивости знаний и прогресса |
| Длительный период | Рост Career Score, карьерная лестница, портфолио, поддержание Verified, новые роли и вакансии | Продолжение развития после основного курса |
| Игровой сезон | Экспедиции, босс, соперники, город, сезонные награды, рекорды | Новые цели и видимые результаты обучения |

Для Career обсуждались decay и refresh навыков: актуальность подтверждения поддерживается повторной проверкой. Конкретные сроки действия Verified, частота пересдач и штрафы не утверждены.

Для опытного разработчика мотивирующими действиями должны стать сложные задачи, ревью AI-кода, интервью, подтверждение навыка, улучшение проекта и соответствия вакансии. Увеличение времени в приложении — ожидаемый эффект этих полезных действий, а не основание выдавать пустые квесты или искусственный прогресс.

## 8 Десять механик Bytecraft World

### Code City

Игрок развивает виртуальную IT-компанию. Обучение приносит награды, за монеты улучшаются здания, а улучшения усиливают последующие результаты. Концепция требует, чтобы состояние компании было связано с освоением навыков и действиями игрока.

В World 0.4.0 есть пять зданий: офис, Python Lab, R&D, серверная и команда. Их уровни дают конкретные игровые эффекты; таблица правил приведена ниже.

### Экспедиция

Идея — короткое приключение из связанных coding-задач с общей целью и сундуком в конце. В первоначальном представлении экспедиция задумывалась как ежедневная активность.

В 0.4.0 реализована сюжетная экспедиция «восстановить API» из пяти разных проверяемых заданий. Её завершение открывает проект калькулятора. Автоматическое ежедневное создание новых экспедиций не подтверждено как часть этой версии.

### Boss Fight

Босс Bug Lord олицетворяет сложную проблему. Правильное решение должно наносить урон; ошибочный ответ не должен уменьшать HP. Победа даёт значимую награду и закрывает сюжетную цель.

В 0.4.0 босс открывается после проекта и содержит четыре разные уязвимости. Каждое верное решение снимает 25 HP из 100.

### Ghost PvP

Исходная идея — асинхронное соревнование с результатом другого игрока по времени и качеству решения. Нужен повод улучшать собственное решение и возвращаться за рекордом.

Текущий режим 0.4.0 измеряет время личной попытки от появления задания до верного ответа. Выдуманная таблица соперников убрана. Реального сетевого Ghost PvP пока нет; рекорд между разными задачами не является нормированным рейтингом сложности.

### Guilds

Идея — команда с общей целью, недельным проектом и личным вкладом. Совместный результат должен складываться из реально выполненных задач.

В 0.4.0 это локальный учебный проект с целью 160 вкладов. Вклад появляется за проверенное решение и зависит от уровня здания «Команда». При достижении цели выдаётся однократный бонус. Настоящая сеть гильдий, чат и синхронизация участников не реализованы.

### AI Rival Kai

Идея — персональный соперник, который предлагает задачи, мотивирует улучшать код и растёт вместе с пользователем. Обсуждались ограничения на длину решения и сохранение корректности на тестах.

В 0.4.0 Kai обозначен как учебный соперник с заранее подготовленными заданиями. Победа засчитывается только за верный ответ; следующее испытание меняется. Подключённая LLM и автономный анализ произвольного кода не подтверждены.

### Mistake DNA

Идея — индивидуальный профиль ошибок и тренировки слабых мест. Реальные ошибки курса и игровых задач определяют, что нужно закрепить.

В 0.4.0 используются счётчики незакреплённых ошибок по укрупнённым темам. Неверный ответ добавляет ошибку; правильная тренировка уменьшает счётчик выбранной темы на один. Выдуманные начальные проценты заменены реальными значениями.

### Build to Unlock

Идея — открывать следующий этап через практический проект, а не через формальную галочку. В ранней подаче упоминалось открытие главы Functions после создания калькулятора.

Текущая цепочка 0.4.0 проверяет четыре компонента калькулятора: базовые операции, историю, обработку ошибок и формат результата. Готовый проект открывает босса World. Это не означает автоматического изменения правил разблокировки всех модулей основного курса.

### Seasons

Идея — сезонная цель и дорога наград, поддерживающие интерес на протяжении нескольких недель. В обсуждении присутствовали аватары, скины, титулы, фон профиля и общая цель сообщества.

В 0.4.0 действуют уровни сезона за XP, монеты и алмазы. Несуществующие косметические награды и выдуманный прогресс сообщества не выдаются за работающие функции. Полноценное расписание сезонов, магазин сезонной косметики и общий онлайн-прогресс остаются развитием концепции.

### Infinite Coding Run

Идея — бесконечная последовательность меняющихся задач, рост сложности, серия правильных решений, жизни и личный рекорд. Ошибка должна иметь последствия, а повторная попытка — сохранять смысл.

В 0.4.0 правильный ответ продолжает серию, неверный отнимает жизнь и сбрасывает текущую серию. Рекорд сохраняется. При нуле жизней отправка решения запрещена в самой логике игры. Восстановление стоит один алмаз. Задачи следуют общему числу решённых, поэтому ошибка не возвращает игрока к простому фарму стартовых задач.

## 9 Связи и экономика игрового мира

### Сюжетная последовательность

**Восстановить API — 5 задач → собрать калькулятор — 4 компонента → победить Bug Lord — 4 уязвимости.** Всего 13 проверяемых сюжетных заданий.

Экспедиция включает расчёт скидки, защиту от деления на ноль, чтение данных ответа API, фильтрацию заказов и проверку готовности сервиса. Проект проверяет компоненты калькулятора. Босс проверяет накопление суммы, границы диапазона, возврат результата и корректную работу с отрицательными числами.

Повторяемые режимы используют условия, циклы, индексы, типы и функции; параметры меняются с продвижением. В тренировке сохраняется выбранная тема. Сложность формируется по числу решённых задач, с ростом параметров каждые пять решений.

### Что меняет результат ответа

- Пустой ответ ничего не завершает и не приносит награды.
- Неверный ответ оставляет текущий этап незавершённым, добавляет ошибку по теме и не выдаёт награду.
- После ошибки базовый XP за последующее правильное решение этой задачи уменьшается вдвое с округлением вниз; бонус R&D за чистое решение не начисляется.
- В Infinite Run ошибка дополнительно отнимает жизнь и обнуляет серию, но сохраняет рекорд.
- Правильное решение продвигает конкретную задачу, выдаёт рассчитанную награду и объясняет изменение состояния.
- Старое задание и повторные быстрые нажатия не должны повторно выдавать награды.
- Первое завершение уровня курса приносит World-награду; повторное завершение того же уровня не позволяет получать её заново.

## 11 Техническая основа

### Архитектура

Для мобильного клиента выбраны Flutter и Dart с общей кодовой базой. Логика организована по функциональным областям с разделением domain, data и presentation. Riverpod отвечает за состояние и зависимости; GoRouter — за переходы; прогресс хранится в локальных JSON-документах с версией схемы через абстракцию хранилища и SharedPreferences.

Уровни описываются данными JSON. Level Engine отвечает за допуск к заданию, проверку ответа, ошибки, награды, жизни, прогресс и открытие следующего шага. Виджеты собирают ответ и отображают результат; право на награду не должно определяться самой кнопкой.

Обучение задумано как offline-first. Для аналитики, AI Tutor, монетизации, авторизации, синхронизации и лидербордов предусмотрены интерфейсы и адаптеры. Наличие интерфейса или mock-реализации не равно подключённому облачному сервису.

### Выполнение и проверка Python

Расширенная песочница использует Pyodide — Python в WebAssembly внутри WebView. Учитываются ограничение времени и объёма вывода. Для отдельных возможностей стандартной библиотеки предусмотрены совместимые механизмы и ограничения мобильной среды.

Генератор учебного контента исполняет примеры настоящим Python и проверяет ответы. Задачи на написание программ проходят тесты. Для World создан отдельный экспорт заданий, который позволяет независимо сверять ожидаемые ответы исполнением в CPython.

### Сборка и проверка

Проект хранится в GitHub, репозиторий pazzia/Python.io. CI проверяет анализ кода, тесты, контент, сборку release APK, подпись, идентификатор пакета и запуск в Android-эмуляторе. Для установки поверх предыдущей версии важны постоянная подпись и увеличенный номер сборки.

По результатам работы над World 0.4.0 подтверждены 175 прошедших Flutter-тестов, проверка 463 ответов в CPython, сборка APK и успешные установка и запуск на Android. Эти результаты относятся к проверенному коммиту, а не к обещанию отсутствия любых будущих ошибок.

### Что потребовало исправления

В 0.3.1 игровые экраны могли начислять результат без проверки ответа. Одна и та же программа показывалась на разных этапах, проект отмечался свободными галочками, рекорды и часть статистики задавались заранее. Пользователь прямо указал, что можно ничего не сделать и нажать «выполнено».

В 0.4.0 эти переходы заменены проверкой активного задания. Добавлены ограничения по предыдущим этапам, защита от повторной выдачи наград, последовательная запись состояния и сохранение прогресса после перезапуска. Ошибка сохранения не должна оставлять в интерфейсе неподтверждённую награду.

Уточнены группы ошибок курса. Подтверждённый сброс профиля очищает и учебный, и игровой прогресс. Главный экран показывает текущую сюжетную цель, а результат ответа автоматически становится видимым и объясняет изменения.

### Переход со старой версии

Старые непроверенные игровые отметки, рекорды, ошибки, World XP, серия и сезонный прогресс сбрасываются. Прогресс основного курса, монеты, алмазы и купленные здания сохраняются; уровни зданий ограничиваются пятью. Приложение объясняет переход, а миграция выполняется однократно.

Последний подтверждённый коммит World 0.4.0 — `ebffd923c52bd779774aaca6d3af4f867add4393`, сборка Android — № 18. Отдельное разрешение на публикацию версии 0.3.1 ранее касалось локального коммита b52ab90; в GitHub эта версия появилась как 092a7f1. Эти идентификаторы относятся к разным этапам истории.

## 14 Первоначальные десять идей головоломки

Эти варианты были рассмотрены до выбора обучающей игры. Они сохраняются как история идей, а не как одновременно утверждённые части Bytecraft.

1. **Time Loop Room.** Комната возвращается к исходному состоянию каждые 60 секунд. Игрок использует знание прошлых циклов, чтобы найти выход.
2. **Shadow Path.** Персонаж и его тень движутся по разным правилам. Нужно одновременно привести обоих к выходу.
3. **One Move Ahead.** Игрок заранее видит последствия через один–три хода и строит решение на прогнозировании будущего.
4. **Crime Board.** Расследование по фотографиям, сообщениям, картам, звонкам и временной линии. Нужно находить противоречия и делать выводы.
5. **Gravity Lab.** Игрок меняет направление гравитации, чтобы доставить объект к цели через препятствия.
6. **Impossible House.** Дом с невозможной геометрией: необычные переходы между комнатами, дверями, лестницами и окнами. Обсуждались дополнительные дома и главы, подсказки и косметические темы.
7. **Merge Machine.** Из шестерён, лазеров, проводов, труб и датчиков собирается система с заданным поведением. Обсуждались дополнительные наборы механизмов и challenge mode.
8. **Silent Signals.** Расшифровка неизвестного языка по символам, жестам и реакциям существ почти без текста. Обсуждались новые миры, языки и истории.
9. **Tiny Heist.** Планирование ограбления с учётом охраны, камер, дверей и лазеров. После запуска составленный план выполняется автоматически.
10. **Broken Reality.** Изменение правил уровня: вода становится твёрдой, красные объекты проходят сквозь стены, маленькие становятся тяжёлыми. Обсуждались пакеты правил, главы, подсказки и редактор уровней.

В общем обсуждении этих игр фигурировали реклама, подсказки, дополнительный контент, сезоны и редактор уровней. Детальный бизнес-план для каждого варианта не фиксировался как окончательный выбор.
